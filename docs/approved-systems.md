# 已批准系统实装记录（0.6.0）

本批依据已经确认的规则接入完整运行路径。未定的内容数量、技能数值、学习树和地图权重使用 JSON 中明确标注的开发配置；不将开发配置视为最终玩法。当前代码默认饰品槽为开发用的 4；2026-10-09 已确认标准为 12 槽，待后续实装同步。背包为已确认的 27 格，装备另占 9 格。

## 战斗与状态

`pkg/damage` 同时返回数值与计算步骤。一次命中只发出一次 `hit`，多个伤害段共用暴击判定，每段分别扣护甲；普通加算、同名乘区加算与异名乘算、最终加算、暴击、最终伤害、护甲、类型抗性、分别相乘的百分比减伤、最低伤害依次求值。魔力和电磁忽略护甲，明确免疫为 0。护盾在生命前消费，记录吸收、实际生命损失及过量伤害。各段发出 `after_damage`，追加伤害不重新产生命中，生命偷取只针对攻击造成的实际生命损失。

状态保留整体等级，各层独立计时、独立快照。默认来源是玩家及技能槽或物品实例；唯一状态拒绝其他玩家，冲突默认替换，满层刷新最后一层。普通状态使用冒险时钟，离场保留，明确声明才离场清除或随卸装移除。装备及限时状态改变最大生命时保持当前生命比例。周期伤害/回复、束缚、眩晕、沉默、类型免疫、等级贡献已接入。Shift 明细包含周期效果的施加时属性及公式。

护盾是无等级状态；多来源叠加，同来源覆盖，优先消耗最新护盾，不自然恢复。倒地惩罚线性每层减少 25%，计数与可清除惩罚分离。**死亡复活后当前倒地计数设为 1，累计历史不清空；之后两次倒地可救援，第三次再次死亡。**同层复活保留个人行动力，新层按新层初始值恢复。复活设施支付开发配置中的货币费用，恢复满生命，保留现有惩罚。

近战使用短前摇后的静止剑气与后摇；攻击速度缩短两段时间。移动剑气、追踪、穿透、共享暴击、多类型武器及换装限制由内容声明。客户端六边形 A* 导航考虑静态障碍与当前敌人，服务端仍逐步裁定移动。敌人使用距离与造成伤害的威胁值、就近攻击机会、远程弹幕、血量阶段改变弹幕与速度、控制抗性，以及随层变化的生命、攻击、护甲、抗性、移速和射速。

跨宿主通过脱离世界的动作值交接，继续前摇、冷却、闪避/无敌及充能；支援、清房和 BOSS 集结共用此路径。射弹经协调者沿连通六边形转交，坐标转换保持世界位置，寿命和命中记录不重置。房外玩家射弹不伤害未参加战斗房间的敌人，也不发命中效果；敌方射弹可在普通空间按共用公式伤害玩家。清波/清房保留已有射弹，暂停规则继续生效。

## 装备、掉落与交换

物品具有稳定实例 ID，修饰和强化属于实例。9 个装备位为武器、头、身体、腿、脚及四消耗品，装备不占背包。普通模式容量有限；特殊模式可配置背包与饰品槽，饰品 `-1` 为动态扩容。武器预览、实际结算与装备比较共用数值模块。

背包保存独立格位引用，移除/装备/消耗不补位。服务端鼠标槽支持左键整堆拿取、放下、合并/交换；右键向上取半堆或放 1。装备不能堆叠，消耗品默认上限 30，并允许 JSON 声明更小上限。堆叠兼容比较已有实例数据，拆分创建新的所属玩家实例 ID。消费减少 1，整堆出售价值按数量计算，拾取/奖励/交易共用合并后填空格的纯事务。

关闭背包、断线与离线恢复回收鼠标槽，预留回收容量；失败不改变输入库存。鼠标操作携带库存版本，过期操作拒绝；客户端仅做脱离权威状态的显示预览。窗口内右键不会变成移动指令。

掉落独立归属玩家，满包时保留地面物品；拾取需要靠近。商店支持购买、出售和当前武器强化，出售价值包含修饰与强化。背包、护甲、饰品、掉落和商店窗口已经接入真实数据。

交换不限制房间、距离或战斗状态，直接交易货币没有入口。双方确认同一报价版本，库存变化会使确认失效；容量与所有权先计算，再由各场景所有者提交。断线关闭交易。已装备物品先卸下再放入报价。交易、购买、使用与换装失败均不留下部分扣除。

技能使用四槽、资源和冒险时钟冷却；消耗品使用真实物品实例。开发内容包含护盾、加速、法力弹、束缚弹、固定值加成治疗、周期治疗、支援信标与解除诅咒道具。支援先验证目标与完成入场，成功后消费道具。

## 地图、成长与恢复

地图按种子、层号和开层人数生成，六边形节点与相邻连接固定到层结束。房间模板在重复使用前去重，微小敌人生命差异由开发配置控制。地图不因层内人数或行动力加成变化而重排；完成普通/强化 BOSS 后结束本层。房间目标支持清敌与限时坚守，经验/货币支持独立份额或固定总量分配，内容可借此鼓励不同参与人数。

局外进度包括加成点、前置学习、属性、初始货币、初始装备、机体解锁、每层行动力和特殊节点。个人加成独立应用，行动力取团队最高总加成，特殊节点按团队是否解锁应用；开层成员记录用于恢复一致性。每类局外加成可在开局前限制。胜利将全部持有装备入库，通关、成就与挑战奖励只结算一次；主冒险不能从仓库带入装备。普通和玩法模组/特殊模式进度分区保存，后者不能回流普通进度。

房主通过独立管理员口令认证；独立服务端可用 `HSM_ADMIN_TOKEN` 配置。管理员可导出最近层间检查点，在个人大厅填写恢复文件并开启恢复，或使用服务端 `-restore`。检查点验证冒险标识、内容摘要、生成地图、层初始行动力、库存来源与属性投影。恢复不等待旧成员到齐，旧成员需要在该层开始前回归。

## 结构与扩展

公式、状态、库存、地图、依赖解析和局外结算是显式值输入的函数式核心；网络、文件、VM、渲染和提交由宿主边界负责。协调器拥有团队状态，每个战斗场景拥有自己的 goroutine、VM 和状态。跨场景交易通过短暂预留及值提交，不传可写世界引用。

当前房间和周围一圈动态实体按同一服务端时间采样。玩家与射弹位置先转换为共同世界坐标插值，再转换到最新房间坐标；射弹具有跨宿主稳定显示标识，新建宿主使用独立标识前缀。仅显示最新实体集合，创建/销毁不延迟；瞬移/复活的玩家位置 epoch 仍阻断错误插值。该改动不修改服务器碰撞和伤害资格。

协议 12 为射弹提供已模拟时间 `age`，服务端固定逻辑步进增加，跨宿主保留，零时间的转交碰撞检查不增加。新射弹缺少插值前样本时从已接收样本反推首次位置，最多回退其已模拟时间；显示时间尚未追上时保留发射位置。这样不会先画最新位置再突然回到旧位置，短暂近战剑气仍立即显示。两帧齐全后使用原有世界坐标插值，删除仍立即生效，不预测碰撞或修改伤害。

战士预设沿用 `base:bulwark` 原卫士数值和剑，保留内容 ID，名称统一为战士；个人大厅右上增加机体选择，点击保存并用于单人/联机。未解锁机体仍受原有局外规则约束，不新增职业限制。初版 PNG 地面和战士贴图使用现有内容资源管线，内置资源随三程序打包；资源发布后使房间与大厅绘制缓存失效。角色透明区域只在加载时求包围框，原图不改，按比例绘制并共用同一图像作预设头像。当前没有动作动画或方向序列。

UI 采用深蓝、青色和金色的共享边框、槽位、资源条样式，基础技能与消耗品使用不同图标。技能栏下方新增货币、等级和经验条，Hover 给出精确经验和待分配点数；顶部显示层数与房间/波次。这两个面板沿用 HUD 拖动保存，较窄窗口缩减中央栏宽以避开两侧；布局编辑工具条让出顶部进度栏。经验阈值从原有 `等级×20` 提取为同一纯函数，服务端和 UI 共用，成长规则未变。

Hover 使用集中语义颜色、14px 正文/24px 行距、分隔标题、内容宽度与屏幕边界约束。属性、伤害类型、生命/护盾/能量和数值在中英文间共用语义角色。删除原始实例 ID、重复基础贡献和无作用步骤；保留有效乘区及计算来源。药剂不再显示无关的当前武器公式，非武器装备只有伤害变化时才附加伤害明细。

JSON/JS/资源模组支持组合、SHA-256 安装校验、范围依赖、精确锁定、多版本、服务器下载及单局外原子重载。资源支持图像、字体、界面主题与布局、WAV 音效及音乐；材质包不改变玩法摘要，可由玩家独立启用。JS 编译结果按路径与源码摘要复用；房间静态绘制按周围一圈缓存。加载记录读取、解析、校验、编译、注册与摘要阶段耗时。

Go 模组单独编译为归档，然后借助 Go 缓存静态重链接宿主。原源文件不被改写，三程序全部成功才发布新目录和 `active.json`；失败保留旧程序。SDK/宿主源码随开发包提供，无 Go 时手动构建入口可下载经 SHA-256 校验的官方工具链。详细用法见 [模组指南](mods.md)。

本批不部署公网服务，不接入 Steam 创意工坊，不制作正式美术或替用户确定平衡。两台独立设备、八人分房、延迟与长期存档验收由玩家按 [待测清单](implementation-audit.md) 安排。
