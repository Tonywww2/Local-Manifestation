# 局部显现 / Local Manifestation — Windows 开发版本 0.7.0

已批准的基础系统已接入，内容和数值仍是可替换的开发配置。当前能力见 [实装记录](approved-systems.md)，实际检查与玩家待测见 [核对清单](implementation-audit.md)。协议 13、SDK 6、内容格式 3、检查点 6；同时更新两端与内容。本批接入第一层敌人、装备、30件饰品、12槽及五层主流程，新增敌人阶段和效果快照。摘要变化后旧默认检查点不兼容；[本批记录与待测](history/content-batch-01-stage.md)。

## 启动

解压开发包运行 client.exe。开始游戏进入个人大厅，走近装置按 G：单人直接开始；房间设置保存配置；创建联机大厅开服；加入服务器填写地址和昵称。联机管理员在准备窗口开始本层。默认允许单人开始，人数默认上限 8，可配置到 128。

其他电脑使用相同版本和玩法组合，输入房主局域网地址及端口，如 192.168.1.10:7777。联机主持监听 0.0.0.0，单人服务监听回环。没有新增公网部署或 Steam 接入。

```powershell
.\bin\server.exe -listen 0.0.0.0:7777 -players 8 -tps 30
.\bin\client.exe -name Alice -profile alice
.\bin\client.exe -name Bob -profile bob
```

同电脑多客户端使用不同 profile。客户端房主自动认证为管理员，返回大厅或关闭客户端会结束它启动的服务器。独立服务器可设置 HSM_ADMIN_TOKEN，在加入表单填写；未设置时保留首个连接者管理的开发行为。

## 操作与规则

默认 WASD、左键攻击、空格闪避，技能 Q/E/R/F（鼠标模式 Q/W/E/R），消耗品 1–4。F2 鼠标模式，Tab 视角，M 大地图。设置内有完整中英文玩法说明、按键、语言与 HUD 布局。

个人大厅右上角护甲按钮选择初始机体并保存，战士沿用原卫士配置，持剑近战。战士图像目前是静态单姿态，其他角色/敌人仍是基础图形。右下背包 / 状态卡片合并原武器、护甲、背包与货币成长入口，显示武器、金钱、等级、经验数值和进度条；悬浮查看未分配点数，Shift 查看计算。顶部显示层数与房间/波次，栏位可拖动保存。窗口、槽位和资源条使用统一边框，地面保留可见六边形网格。[基础美术来源与提示词](art-assets.json)随包提供。

0.6.1 接入简约近代视觉。主菜单仅开始/设置/退出，按钮和文字为真实控件；个人大厅由三个六边形拼合，六个设施使用基地家具表现，右上显示当前进度范围内的真实局外点数。家具为基础矢量布景，未新增角色素材或职业规则。战斗 HUD 使用统一石墨灰面板与白色图标，冷却不再覆盖快捷键，生命数字放进血条，闪避圆点在右侧，队友显示生命条与房间标识。640 宽度时层数栏移到左侧，避免压住技能；保存过的自定义布局仍优先生效。冒险随机房间的复合形状尚待接入。

地图只用于查看，走到入口跨房。免费通路连续通过；个人门口 G 后确认；共享门口/出口装置投票需留在范围内。普通战斗前和波次间可加入，开战锁门。波次间仍可操作；全房倒地暂停，外部队友清理后救援。全队倒地/死亡判负。

普通房间与层间准备可攻击、闪避和释放技能；停止输入仍恢复闪避次数。个人大厅也可攻击和闪避。资源、冷却与控制效果按既有规则生效；后续安排见 [下一批计划](next-implementation.md)。

跨战斗边界继续攻击前摇并保留冷却、闪避/无敌剩余和充能。射弹按连通房间跨界运行，保持世界位置与剩余寿命；未参与该房战斗的玩家不能通过射弹伤害房内敌人。清波/清房不再直接清空已有射弹。

背包左侧为角色立绘与武器、四护甲，左下为消耗品与当前技能；右上为饰品，右侧其余区域为27格背包。标准12饰品槽已接入，特殊模式可调整。“属性与加点”打开独立窗口，关闭背包后仍保留，可分配点数、查看详细属性与计算。左键取放、右键半堆/单个，格位不自动整理。在商店附近购买/出售/强化；靠近掉落拾取。点击队友状态可交易，双方确认同一报价，不限制房间/距离/战斗，不能直接交易货币。

Hover 随鼠标只读，Shift 展开，不可拖动，无关闭/确认；状态左键不另开页面。普通窗口可多个同时存在、拖动、关闭与滚动，均不暂停。行动力在小地图左下，闪避圆点在血条右侧。

小窗口中的背包、交易、房间设置和设置可滚动内容，标题/底部操作固定；标题箭头也可滚动。扩容背包与饰品使用各分区标题旁的箭头分页。装备 Hover 使用完整属性投影比较，满背包也能显示真实加成；Shift 查看具体变化和公式。此次界面改动的检查与待测见 [背包界面记录](history/inventory-ui-stage.md)。

F4 帧率上限、F5 VSync、F6 实际频率。服务端逻辑、快照和渲染独立；客户端 Update 为 60 TPS，渲染按用户上限，服务器 30/60 TPS。选择上限不保证设备能达到该帧率。

## 进度与恢复

通关物品入库，局外点数与成就/挑战按冒险标识结算一次。个人大厅学习加成/查看仓库，主冒险不能带入仓库装备。玩法模组与特殊进度单独保存，不能回流普通进度。profile 的 .progress.json 保存成长；损坏时阻止覆盖，先备份/修复该文件。

管理员开始本层前保存层间检查点。客户端主持使用 data/hosts/<profile>/checkpoint.json。管理员可在设置/准备页导出最近检查点，在房间设置填写恢复文件并开启恢复；留空使用上次文件。独立服务端：

```powershell
.\bin\server.exe -restore data/checkpoint.json
```

恢复需要相同内容、组合版本/顺序及 SHA-256。不等待原队伍到齐；旧成员需要开层前回归。检查点不保存中途战斗。种子和开始时间生成冒险标识，用于去重身份，不是账号防作弊服务。

## 开发

内容位于 content/base，两端可用 -content 指定外部目录。模组设置与 Go 构建见 [模组指南](mods.md)。开发包附 sdk-source，供静态重链接使用，第三方许可证随包提供；项目本身许可证尚待选择。

```powershell
.\tools\build.ps1
.\bin\modtool.exe validate -dir content/base
.\tools\package.ps1
```

每轮默认仅编译和绝对必要的少量运行检查，不自动执行全量测试、竞态或性能回归。正式美术、内容平衡与独立设备验收继续按用户安排推进。
