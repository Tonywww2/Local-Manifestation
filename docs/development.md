# 局部显现 / Local Manifestation — Windows 开发版本 0.8.0

当前协议 16、SDK 7、内容格式 4、检查点 7。客户端、服务端及内容须同时更新；旧开发检查点不兼容。最新改动见 [核对清单](implementation-audit.md)。内容数值仍使用可替换开发配置。

## 启动

解压开发包运行 client.exe。开始游戏进入个人大厅，走近装置按 F：单人直接开始；房间设置保存配置；创建联机大厅开服；加入服务器填写地址和昵称。联机管理员在准备窗口开始本层。默认允许单人开始，人数默认上限 8，可配置到 128。

其他电脑使用相同版本和玩法组合，输入房主局域网地址及端口，如 192.168.1.10:7777。联机主持监听 0.0.0.0，单人服务监听回环。没有新增公网部署或 Steam 接入。

```powershell
.\bin\server.exe -listen 0.0.0.0:7777 -players 8 -tps 30
.\bin\client.exe -name Alice -profile alice
.\bin\client.exe -name Bob -profile bob
```

同电脑多客户端使用不同 profile。客户端房主自动认证为管理员，返回大厅或关闭客户端会结束它启动的服务器。独立服务器可设置 HSM_ADMIN_TOKEN，在加入表单填写；未设置时保留首个连接者管理的开发行为。

## 操作与规则

默认 WASD、左键攻击、右键武器技能、空格闪避、消耗品 1–4、F 交互。F2 切换鼠标模式：右键移动、中键武器技能。Q/E 连续旋转，滚轮缩放，M 大地图。大地图左键拖动视角，点击目标确认移动；右键菜单的共享投票仅限相邻节点。

个人大厅右上角护甲按钮选择初始机体并保存，战士沿用原卫士配置，持剑近战。战士图像目前是静态单姿态，其他角色/敌人仍是基础图形。右下背包 / 状态卡片合并原武器、护甲、背包与货币成长入口，显示武器、金钱、等级、经验数值和进度条；悬浮查看当前装备和成长信息，Shift 查看计算。顶部显示层数与房间/波次，栏位可拖动保存。窗口、槽位和资源条使用统一边框，地面保留可见六边形网格。[基础美术来源与提示词](art-assets.json)随包提供。

0.6.1 接入简约近代视觉。主菜单仅开始/设置/退出，按钮和文字为真实控件；个人大厅由三个六边形拼合，六个设施使用基地家具表现，右上显示当前进度范围内的真实局外点数。家具为基础矢量布景，未新增角色素材或职业规则。战斗 HUD 使用统一石墨灰面板与白色图标，冷却不再覆盖快捷键，生命数字放进血条，闪避圆点在右侧，队友显示生命条与房间标识。640 宽度时层数栏移到左侧，避免压住技能；保存过的自定义布局仍优先生效。冒险随机房间已支持多六边形拼合。

大地图个人移动支持沿最短通路直接到目标，每条连接消耗 1 点个人行动力；重复、返回也计费。商店和通路默认不阻挡，未完成战斗及特殊事件默认阻挡，完成后可经过。商店可个人进入。共享同行仍限相邻节点，通过后消耗 1 点共享行动力。战斗前等待、波次间也不能离开；清场后停留。

普通房间与层间准备可攻击、闪避和释放武器技能；停止输入仍恢复闪避次数。个人大厅也可攻击和闪避。资源、冷却与控制效果按既有规则生效；后续安排见 [下一批计划](next-implementation.md)。

跨战斗边界保留冷却、闪避/无敌剩余和充能。房间空间独立，弹体留在原房间，不再跨房运行；客户端只显示当前房间，仍预加载邻房资源。清波/清房不直接清空已有射弹。

背包左侧为立绘、武器和四护甲，左下为四消耗品与当前武器技能；右上为饰品，右侧为 27 格背包。装备槽具有分类纹理，标准 12 饰品槽。“属性详情”打开独立窗口；无手动加点，每级六维各 +1 再加 JSON 配置的机体成长偏好。背包左键取放、Shift+左键快速穿戴/卸下，空手右键详情菜单、手持右键放一个，不自动排序。交易不限制房间、距离和战斗，仍需双方确认。

Hover 随鼠标只读，Shift 展开，不可拖动，无关闭/确认；状态左键不另开页面。普通窗口可多个同时存在、拖动、关闭与滚动，均不暂停。行动力在小地图左下，闪避圆点在血条右侧。

小窗口中的背包、交易、房间设置和设置可滚动内容，标题/底部操作固定；标题箭头也可滚动。扩容背包与饰品使用各分区标题旁的箭头分页。装备 Hover 使用完整属性投影比较，满背包也能显示真实加成；Shift 查看具体变化和公式。此次界面改动的检查与待测见 [背包界面记录](history/inventory-ui-stage.md)。

F4 帧率上限、F5 VSync、F6 临时显示帧数与网络延迟。设置 → 性能与网络可分别开启帧数、网络延迟和开发监控，并打开性能详情。服务端逻辑、快照和渲染独立；客户端 Update 为 60 TPS，渲染按用户上限，服务器 30/60 TPS。选择上限不保证设备能达到该帧率。

## 进度与恢复

通关物品入库，局外点数与成就/挑战按冒险标识结算一次。个人大厅学习加成/查看仓库，主冒险不能带入仓库装备。玩法模组与特殊进度单独保存，不能回流普通进度。profile 的 .progress.json 保存成长；损坏时阻止覆盖，先备份/修复该文件。

管理员开始本层前保存层间检查点。客户端主持使用 data/hosts/<profile>/checkpoint.json。管理员可在设置/准备页导出最近检查点，在房间设置填写恢复文件并开启恢复；留空使用上次文件。独立服务端：

```powershell
.\bin\server.exe -restore data/checkpoint.json
```

恢复需要相同内容、组合版本/顺序及 SHA-256。不等待原队伍到齐；旧成员需要开层前回归。检查点不保存中途战斗。种子和开始时间生成冒险标识，用于去重身份，不是账号防作弊服务。

## 开发

内容位于 content/base，两端可用 -content 指定外部目录。模组设置与 Go 构建见 [模组指南](mods.md)。开发包附 sdk-source，供静态重链接使用，第三方许可证随包提供；项目本身许可证尚待选择。

```powershell
.\tools\build.ps1
.\bin\modtool.exe validate -dir content/base
.\tools\package.ps1
```

每轮默认仅编译和绝对必要的少量运行检查，不自动执行全量测试、竞态或性能回归。正式美术、内容平衡与独立设备验收继续按用户安排推进。

## 性能监控与卡顿定位（2026-10-10）

设置 → 性能与网络提供独立的帧数和延迟开关，保存到当前 profile 的设置中。左下角显示实际渲染 FPS 和 ping/pong 往返延迟（RTT），未连接或三秒内无有效回包显示 `--`；RTT 不包含客户端的显示插值缓冲。F6 为临时显示开关。即使关闭显示，低开销的分阶段计时仍记录，方便事后打开详情。

性能详情是普通窗口，可拖动、关闭和滚动，不暂停游戏。三列分别显示客户端、服务端协调/传输、选定战斗房间；多个房间时用第三列标题旁的箭头切换。按照近一秒总耗时排序，提供总耗时、单次平均、P95、最大值和调用次数，附带实际 TPS、实体数量、堆内存、分配量、GC 和累计慢帧。保存图标导出最近最多 120 个采样到 `data/diagnostics/`，报告包含所有战斗房间的阶段统计。

主要阶段：客户端 Update、输入/UI 构建、状态接收、脚本回调、音频、资源/房间缓存加载，以及渲染插值、地板、角色、装置、射弹和 UI；服务端命令、状态、战斗外动作、场景同步、快照构建/广播与网络序列化；战斗房间的玩家更新、敌人属性/AI/寻路/发射、射弹碰撞、命中事务/回调、波次生成和快照。未执行的阶段不会显示。独立服务器的报告另包含每个战斗房间的 TPS、实体数和丢刻数。

```powershell
# 客户端每秒更新 JSON；CPU 采样需显式启用
.\bin\client.exe -profile developer -performance -metrics .cache/client-perf.json -cpuprofile .cache/client-cpu.pprof

# 无客户端窗口的独立服务器也能记录
.\bin\server.exe -tps 60 -metrics .cache/server-perf.json -cpuprofile .cache/server-cpu.pprof

.\tools\go.ps1 tool pprof -top .cache/client-cpu.pprof
```

输出文件的父目录需已存在；正常退出客户端、Ctrl+C 停止服务器后 CPU profile 才完整。JSON 每秒保存，硬终止时可查看最近已写出的采样。诊断文件可能含房间标识，但不导出身份令牌、玩家背包或完整游戏快照。

读取注意：父阶段包含子阶段，不能相加；逻辑耗时按逻辑更新次数、渲染耗时按渲染次数比较。`render.pacing_wait` 是帧率限制等待，`frame.interval` 是端到端帧间隔，均不是逻辑计算成本。渲染阶段为宿主 CPU 提交时间，未测量 GPU 完成时间；延迟执行的绘制工作可能被计入后续调用阶段，必须结合 CPU profile 与对照场景定位。网络写入包含套接字等待。Windows 使用高精度单调计时；P95 为有界直方图估算上界，GC 暂停为运行时直方图估算，不等同于精确追踪。

显式开发冒烟运行可追加 `-smoke-frames 3000 -smoke-duration 20s -smoke-autoplay`，用墙钟时间限制低帧率场景的运行时长。普通游戏不启用这些参数。此次弹幕对照结果与待测范围见[实装核对](implementation-audit.md)。

## GPU 弹幕合批（2026-10-10）

客户端默认使用 GPU 圆形着色器：可见射弹组装为连续顶点/索引数据，每批最多 2048 个四边形提交。敌弹的圆环和中心合为一个四边形，GPU 计算边缘覆盖与颜色；剑气圆环共用这条路径。缩放无需重建圆形遮罩。顶点缓冲区循环复用，索引预生成；屏幕外射弹不提交。清弹扇形保留原表现，前后切批以保持透明叠加顺序。

原引擎本来已使用 GPU，也会自动合并符合条件的调用；这次优化主要减少逐颗绘制的 CPU 调用与数据准备成本。没有把权威战斗、碰撞或数值计算迁到 GPU。客户端逻辑频率、服务端 30/60 TPS、玩家帧率上限及 VSync 设置仍独立生效。

开发者可显式切换到缓存贴图路径进行同场景对照；着色器源码编译失败也会打印原因并采用此路径。两条路径均使用 GPU 绘制：

```powershell
.\bin\client.exe -projectile-renderer batch -metrics .cache/batch.json
.\bin\client.exe -projectile-renderer sprites -metrics .cache/sprites.json
```

性能详情新增上一帧弹幕的可见/裁去数量、合批提交次数、顶点/索引输入量和单图调用次数。JSON 的 `samples[].render` 同时记录这些值；`projectiles` 是绘制输入数，可能因显示插值与同一时刻的权威快照计数略有不同。`quads` 不含沿用矢量绘制的清弹扇形；`batch_submissions` 是宿主提交次数，不能等同驱动最终 draw call 数。`vertex_index_bytes` 按每四边形 216 字节估算本次提交输入，不能当成显卡总线流量或显存占用。`projectile_build` 记录各段数据准备，`projectile_submit` 记录提交，两者由 `projectiles` 父阶段包含，均不是 GPU 完成时间。

渲染主循环独占这些暂存数据，不共享写入模拟状态。首帧提交小尺寸离屏绘制预热管线；角色深度排序改用复用的索引/位置数组，避免逐帧创建绘制闭包。地板网格继续沿用静态几何缓存。

引擎背景见官方[绘制性能说明](https://ebitengine.org/en/documents/performancetips.html)与[着色器说明](https://ebitengine.org/en/documents/shader.html)。实际测量与待测范围见[实装核对](implementation-audit.md)。

## 开发道具目录

进入冒险后按 F7 → 获取任意道具。目录读取当前内容组合中的所有 ItemDef，包含模组注册的物品；名称/ID 搜索和分类分页均在客户端处理，内容组合或语言改变时重建只读索引。领取使用 `debug_grant_item` 意图，`item` 为物品定义 ID。服务端核对管理员身份，通过现有库存事务发放一件；满包或无效定义不提交变化。在战斗房间内，先向房间所有者预留玩家值，再计算完整领取结果并提交，不直接改写房间状态。新增意图沿用现有请求字段。
