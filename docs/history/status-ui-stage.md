## 已确认规则作为实现输入

| 主题 | 本阶段必须遵守的规则 |
| --- | --- |
| 时间 | 普通限时状态使用冒险逻辑时间；地图和层间准备也计时。全房倒地暂停该房间的战斗模拟，不暂停整局冒险时间 |
| 来源 | 同来源为同一施加者的同一个技能或物品实例；不同玩家及不同实例默认独立 |
| 层实例 | 不带等级，各层独立计时；满层再次施加刷新最高层的持续时间，特殊规则由内容声明 |
| 唯一与冲突 | 唯一状态在施加阶段拒绝第二个施加者；已约定的覆盖情形默认替换旧状态，冲突和特殊规则由定义表达；失败不能破坏旧状态 |
| 快照 | 施加时保存效果快照；施加者之后的属性变化不反向改变既有效果 |
| 离场与卸装 | 离场默认保留剩余时间；已施加的限时效果在卸装后默认保留，显式的离场清除或装备绑定规则例外 |
| 生命变化 | 最大生命变化保持当前生命比例；普通难度惩罚每层线性减 25%，第四次倒地死亡，倒地记录与惩罚分离 |
| 护盾 | 特殊状态，无等级；多源叠加、同源覆盖，最新施加的先消耗，不自然恢复，到期移除剩余量 |
| 伤害与触发 | 多类型按独立段分别计算护甲；一次实际命中只触发一次命中事件。只有命中前贡献和伤害后事实，不新增通用“造成伤害时”触发 |
| 装备后续接入 | 战斗中允许更换装备，内容可限制；状态来源已预留物品实例，不用背包下标标识来源 |
| 联机与 UI | 服务端统一裁定，支持分房行动；界面不提供暂停；中英文 JSON 本地化；双视角共用世界坐标 |

这些规则来自[设计记录](../design.md)，其中已回答的生命比例、线性惩罚和第四次倒地死亡不再重复询问。

## 模块与职责

以下是工程拆分提案，具体函数签名与公开 SDK 在编码时确定。

| 位置 | 本阶段改动 | 边界 |
| --- | --- | --- |
| `pkg/model` | 状态定义、状态及层实例、生命记录、来源与序号的纯值类型 | 定义、实例、派生值分开；层实例没有等级；不保存 VM 或世界指针 |
| `pkg/status`（新增） | 施加、替换、刷新、到期、移除、贡献生成及护盾消费 | 显式输入和返回结果；不采样墙钟、不启动 goroutine、不发网络消息 |
| `pkg/stats`、`pkg/damage` | 状态贡献接入；多段请求、结果、吸收及解释 | 实际结算、预览与显示共用求值结果，不写第二套 UI 公式 |
| `internal/content` | 定义加载、生命周期和来源校验、恢复后重建派生值 | 目录发布后只读；未知字段、非法引用和非有限数值拒绝 |
| `internal/scene` | 场景内实体的状态、伤害和生命事务 | 房间 goroutine 独占写入；暂停仍接收冒险时间和救援操作 |
| `internal/session` | 冒险逻辑时间、场景外实体及交接 | 不直接修改场景拥有的玩家状态；按明确交接点转移写入权 |
| `sdk`、`internal/script` | 状态注册、受限施加命令、命中前贡献与事后监听 | Go/JS 契约一致；输入值隔离、来源验证、执行预算及完整提交 |
| `pkg/protocol`、`internal/persistence` | 状态同步、时间/修订信息、层间检查点 | 嵌套值深复制；恢复先校验，再构建运行时 |
| `internal/client/ui`（新增） | 布局、控件状态、焦点/输入捕获、可复用数值与来源行 | 不依赖服务端可变对象，不在绘制阶段发送玩法命令 |
| `internal/client`、`locales` | 界面视图模型、绘制适配、动作发送、中英文词条 | UI 读取已裁定快照；网络操作由现有宿主边界负责 |

不引入无实际调用者的 ECS、通用脚本反射层或大型 UI 框架。先用 Go 值类型和小函数组合已有 Ebitengine 绘制、字体、插值与输入链路；有实测问题再引入缓存或调度结构。

### 状态数据与事务

定义保存显示词条、资源引用、叠加/冲突策略、时间域、生命周期及效果参数。运行实例保存目标、来源、稳定实例 ID、施加次序和施加快照；各层保存稳定 ID 与自己的到期数据。最高层用层次顺序表达，不恢复已取消的等级字段，也不使用数组下标作为身份。

`施加/刷新/移除/到期 → 完整校验 → 新状态集合与贡献 → 派生属性 → 保持生命比例 → 所有者一次提交`。拒绝唯一状态、非法来源或超出运行预算的操作时，旧状态、生命和资源都保持原值。变更返回结构化事实，由宿主提交后广播。

状态变化只使相关派生结果失效。基础值、成长贡献和状态贡献分别保留，避免将状态永久写入机体基础属性，或到期时用反向减法恢复。护盾余额变化不要求重算无关的六种属性。

来源身份与当前持有者分开：离场或装备转移后，旧限时状态仍能引用施加时来源；不能要求来源装备始终在施加者背包中，除非状态明确绑定装备存在。恢复校验必须区分有效的历史来源与伪造引用。

### 冒险时间与交接

新增明确的冒险逻辑时间，不能直接把现有一直增长的 `ServerTick` 当作状态时间。统一整数时间单位覆盖 30/60 TPS，避免两种频率下累计浮点误差。协调器按完成的逻辑刻推进，并向实体所有者传递单调时间标记；这条链路独立于 20 Hz 等网络快照发布。

场景在施加、命中和交出实体前先处理相应时间点的到期；暂停场景停止移动、攻击及房间战斗时间，但仍处理冒险状态到期。交接值携带已处理的时间标记与完整状态，接收者只推进尚未处理的区间。不能由协调器和房间各扣一次持续时间，也不能按客户端 FPS 或本机墙钟裁定到期。

同刻到期与命中、刷新、移除的执行次序必须固定并有边界测试。不通过快照发布延迟延长效果，不让时间推进消息无限积压。具体通道合并及应答方式在接入独立场景循环时测量，保持单一状态所有者。

断线不等于暂停仍在运行的冒险。检查点保存逻辑时间与状态时间数据；停止服务器到恢复之间不擅自加入现实离线时间扣减规则。初始大厅和终局的时间边界在宿主生命周期中明确表达。

### 倒地与多段伤害迁移

现有 `Downs` 同时承担惩罚和死亡门槛，必须拆开。倒地事件记录只由生命状态转换更新；恢复节点降低惩罚不会删除事件记录。惩罚通过统一属性/伤害贡献解释，普通难度倍率按 `1 - 0.25 × 当前惩罚层数` 计算，不将各层分别乘 0.75。救援及复活仍由宿主生命状态机管理，状态到期或生命比例调整不能使倒地者自动站起。

伤害先收集本次命中的数值贡献：提高本次物理伤害并入相应段，追加一次伤害保持独立段。各段按现有公式计算攻击、防御和最低伤害，然后依次消费护盾、扣除生命。结果保留段 ID、伤害类型、每项来源、防御后伤害、吸收量、实际生命损失及过量伤害；护盾完全吸收时生命损失为 0。

攻击/命中/段身份贯穿事件与结果。一个命中的多段不会重复发布命中；追加伤害与周期效果不会默认递归产生新命中。`after_damage` 能读取已提交的生命损失和护盾吸收，生命偷取仅允许攻击，不能把护盾吸收伪装成生命损失。

## 基础 UI：已确认布局与工程提案

默认布局改为用户指定的泰拉瑞亚式全屏叠加 HUD，替换上一版固定主画面/侧栏草案。所有常驻组可在设置中拖动并保存。先用清楚的文字、简单几何占位和少量功能色；最终原创美术风格、图标与动效后续讨论。

### 常驻布局

| 区域 | 已确认内容 | 实现要求 |
| --- | --- | --- |
| 全窗口 | 战斗世界 | HUD 和悬浮窗覆盖其上，不缩小为固定左侧战场 |
| 左上 | 四技能，下方四消耗品 | 各组独立定位，显示已有实际键位 |
| 右上 | 小地图，下方视角按钮，再下方队友状态 | 点击小地图开大地图；同房间队友置顶且有特殊边框 |
| 小地图内部左下 | 个人/共享行动力 | 实际服务端余额；不在血条下重复排列 |
| 底部中央 | 生命/特殊资源条，上方状态栏 | 护盾独立表达；未知资源不虚构数值；来源和时间可检查 |
| 血条右侧 | 闪避圆点 | 实心表示可用，空心表示已消耗 |
| 右下 | 武器、护甲、背包入口 | 背包打开悬浮窗；位置可配置，物品事务随后接入 |

技能和消耗品各四个位置，默认绑定为 Q/E/R/F 或 Q/W/E/R，以及 1/2/3/4；自定义后显示实际绑定。默认只显示图标/快捷键，空槽在 Hover 中说明未装备，不设计技能数值。悬浮背包及护甲窗的布局基础可以先交付，装备、交换等操作只有对应服务端事务完成后才可执行。

现有等级、经验、货币、武器强化和加点操作继续保留：等级/经验在本人信息，详细属性和加点在本人详情，货币及价格在商店等相关节点。整理 HUD 不删除已有功能。

暂停房间有明确“战斗暂停，等待支援”提示；清理完成后才显示可救援操作。倒地、死亡和离线分开显示。强化 BOSS 选项在既有条件满足时呈现，并解释进入前可继续个人行动和救援；不制造共享行动力归零就立刻传送的界面反馈。

### 状态与计算详情

- 默认状态图标只附持续时间和状态整体等级；名称、效果与层数移入 Hover。整体等级不是层实例等级；护盾继续无等级。溢出使用图标入口，同名多来源的详情逐来源列出，不改变服务端叠加。
- Hover 或焦点显示名称、效果、整体等级、施加者/技能或物品来源、各层剩余时间及特殊生命周期；长武器详情可通过普通武器窗口阅读；状态 Hover 不提供固定操作。层行不出现等级。倒地惩罚层数与倒地事件记录分别呈现。
- Hover 使用鼠标绑定的独立只读显示层，不可拖动/固定/滚动，没有关闭或确认按钮；普通窗口可拖动并同时打开多个。具体状态左键不打开额外页面；其 Hover 默认显示简单描述、层数和持续时间，Shift 展开计算与详细来源。
- 护盾独立显示剩余总量；详情列出各来源余额、剩余时间和当前消费顺序。同源覆盖不是刷新旧余额后再叠加。
- 武器按钮只显示图标及已绑定快捷键，Hover 默认显示最终伤害和类型；按住详情键（默认 Shift）展开计算；滚轮/PgUp/PgDn 仅浏览普通武器窗口。来源与公式共用现有结构化结果；点击武器按钮打开普通武器窗口，便于阅读长内容。
- “预计攻击伤害”与“最近实际结算”明确区分。后者依次列出攻击、护甲/抗性/减伤、护盾吸收和生命损失，多段逐段可查。界面不把未知敌人防御当作已知数据。
- 详情使用悬浮检查窗，战斗世界仍覆盖整个窗口；打开详情不暂停冒险。紧凑窗口采用可定位的窗口与分页详情。

敌人常驻信息只显示可读的生命条与关键状态标记；高生命的数字隐藏沿用已确认规则，具体阈值留给显示配置，不在此新增。详细来源不在所有敌人头顶堆满文字。

### 连接、准备与设置

连接页沿用地址、名称、机体选择和创建本机服务器功能；准备页沿用队伍、当前层信息及管理员开始按钮，单人也能开始。两页复用同一套按钮、输入框、通知和本地化显示行，不在本阶段增加匹配大厅、账户或好友系统。

设置主页提供语言切换、按键自定义和布局编辑；输入模式、帧率上限和 VSync 继续集中在设置。HUD 不另放语言切换按钮；所有按钮默认使用图标/已绑定快捷键，详情经 Hover 显示。按键子页区分两种输入模式，绑定草稿、冲突校验与输入消费边界见[专项计划](hud-navigation.md)。现有 F2/F3/F4/F5/F6 功能继续保留，F6 诊断与玩法 HUD 分开。游戏内设置仅修改客户端配置，不暂停服务器。连接中、内容不匹配、连接失败和重连等待使用不同的反馈状态，已有身份配置不因界面切换丢失。

### 布局、输入与本地化实现

原生 HUD 已按实际窗口尺寸布局，命中区域在 `Update` 中生成，攻击使用全窗口相机反投影。UI 状态处理链为：`快照 + 本地 UI 状态 + 窗口尺寸 → 视图模型/布局 → 输入动作 → 宿主发送`；绘制只读布局和值。旧连接表单暂保留原有按钮适配，其输入也服从窗口捕获。

1280×800 作为基准设计尺寸，同时验收 1024×720 紧凑窗口和 1920×1080，通过锚点/偏移布局保持文字可读，不仅缩小整张固定画布。战斗相机使用整个窗口，HUD 命中检测独立于世界反投影；实体插值继续复用。俯视/斜俯视切换只影响世界显示，HUD 位置不变。配置保存与实际跨房的完整边界见[专项计划](hud-navigation.md)。

UI 捕获的点击、滚轮和按键不能同时变成攻击、移动或节点操作。鼠标在详情区域仍可瞄向战场，但不会点击按钮时同时开火；焦点、输入框和面板关闭由 UI 状态处理，不在网络层猜测。面板操作不擅自吞掉已确认的移动/技能绑定，具体焦点行为用原生客户端验证。

界面选择绑定实体/状态/层的稳定 ID，不绑定列表下标；状态到期、队友重排或重连不会把详情切到另一个来源。来源、数值和层剩余时间使用可组合的显示行，后续装备比较及交换可以复用。

中英文文本全部来自 JSON，包括状态说明、空槽、拒绝原因和通知；保留英文/词条键回退。长英文、八名长名称、长来源名、数十层状态和缺失图标都需有截断/换行/查看完整内容的行为。普通 HUD 不暴露内部 ID、Go 类型、脚本处理器名或调试 TPS；诊断仍由 F6 单独显示。

倒计时可按服务端快照时间作显示推算，但客户端不删除状态、不扣护盾、不修改属性；超过可推算窗口时显示等待同步，不能在网络断流后一直假装获得新裁定。视图模型按快照修订/语言/布局变化更新，渲染帧只做显示工作，不逐帧完整求值或复制所有详细公式。

性能以现有时序基线为对照，记录状态施加/到期/伤害热路径耗时与分配、八个活动场景 TPS、实际 FPS、消息字节数及加载时间。当前帧上限已提高至 4 MiB，并验证八人状态预算；复杂效果继续检查传输负载：不向所有成员每次快照广播全部展开公式，按显示用途拆分摘要与详细数据；如需调整传输结构，在协议实现与负载测试中一起完成。

两台独立设备和公网可达性仍是项目最终验收项，本机双连接不能替代它们。
