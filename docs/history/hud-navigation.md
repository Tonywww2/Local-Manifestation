# HUD 布局与实际跨房移动

用户于 2026-10-07 确认，2026-10-08 更新。本页取代固定主画面/侧栏布局。U1/U2 的原生 HUD、悬浮窗、Hover 和设置已接入；房间六边形场地/网格、免费通路、实际入口、周边一圈加载、本机普通移动预测与实体投票已接入；限时属性状态与冒险时钟已接入，护盾/特殊状态与障碍导航仍待实施。大地图只查看，走到入口进行跨房。已交付范围见[原生 UI 实现记录](ui-stage.md)、[房间修正](rooms-stage.md)及[跨房实现](doors-stage.md)，下文的其余状态和空间要求仍是后续实现输入。

## 已确认的默认 UI

战斗世界绘制覆盖整个窗口，HUD 和悬浮窗叠加在世界上，不为常驻队伍栏、技能栏或资源条切出固定世界视口。默认排列参考用户指定的泰拉瑞亚式 HUD；美术使用原创占位资源。

| 位置 | 内容 |
| --- | --- |
| 左上角 | 四个技能位置 |
| 技能栏下方 | 四个消耗品位置 |
| 右上角 | 小地图；点击打开与现有地图类似的大地图 |
| 小地图内部左下 | 个人和共享行动力 |
| 小地图下方 | 视角控制按钮；快捷键入口保留，当前 Tab 功能继续支持 |
| 视角按钮下方 | 队友状态；同房间队友置顶并使用特殊边框 |
| 屏幕中间最底部 | 生命和特殊资源条，护盾独立表达 |
| 血条右侧 | 闪避储存圆点；实心可用、空心已消耗 |
| 资源条上方 | 状态栏 |
| 右下角 | 当前武器、护甲和背包按钮；点击背包打开普通窗口 |

“1–4 技能”表示四个技能位置，不擅自改成数字键释放：按此前规则，键盘移动模式使用 Q/E/R/F，鼠标移动模式使用 Q/W/E/R；消耗品仍为 1/2/3/4。以后调整按键通过独立输入配置实现，不与拖动 HUD 混为同一设置。

同房间依据服务端认可的空间身份判断，不能仅将两个空 `Scene` 字符串当作同房间。同组内部使用稳定成员顺序，避免血量每次变化都重新排序。默认八人房间显示七位队友，本人生命与资源在底部；更高人数提供同房间优先的列表浏览。离线、倒地和死亡分别显示。

特殊资源条的显示由实际资源定义提供。这里不新增魔力池、怒气等具体玩法；尚无资源时不伪造可用数值。状态详情、护盾来源及 Shift 伤害明细改为悬浮检查窗，不再将战斗画面缩成左侧区域。

## 设置与 Hover（2026-10-08 补充确认）

语言切换、按键自定义和 UI 布局编辑统一从设置页面进入。取消 HUD 上单独的语言切换按钮。语言子页默认支持中文/英文，选项名称使用各语言自身的名称；保存后刷新已打开的设置、HUD、Hover 和窗口标题。原生文案继续来自 JSON，本地化不改变组件 ID、动作 ID 或内容 ID。

按键子页分别编辑键盘移动和鼠标移动两种输入模式，覆盖移动、攻击、技能、消耗品、闪避和已有界面快捷动作。使用稳定动作 ID 保存按键，不保存本地化名称；图标旁快捷键和 Hover 提示从同一绑定结果派生，禁止另写一套固定按键文字。修改使用草稿，支持取消、恢复默认与保存；在同一输入上下文发现冲突时提示并阻止该修改，不静默覆盖另一动作。捕获按键/鼠标键、设置表单和布局编辑优先消费输入，不能同时释放技能、移动或攻击。具体多键组合/保留键与模组动作契约在输入模块接入时确定；浏览器草案不替代原生按键支持。

按钮默认只展示图标和已绑定快捷键，没有快捷键的按钮不伪造一个；名称、说明、操作结果、禁用原因在 Hover 中显示。设置表单的动作/字段名称仍作为按钮外的文本标签显示，保证按键配置可辨认。小地图、队友生命/身份和资源条属于信息显示，不因为使用可点击控件就删掉必要的地图/状态信息；它们的额外说明也接入 Hover。空槽显示占位图标，Hover 说明未装备，不制造技能效果。

状态栏默认展示状态图标、持续时间和**状态整体等级**；用户已明确这不是每一层的等级。层实例继续没有等级，并独立计时，Hover 展开名称、效果、整体等级、施加者及具体技能/物品来源、每层剩余时间、层数和特殊生命周期。整体等级与层数分别表示；本次仅确认其展示与数据归属，不新增等级提升/效果缩放规则。护盾保留无等级的特殊规则，等级位置省略而不是显示虚构等级；永久状态使用明确的永久标记。多层的简要时间需要表示为可区分的计时摘要，完整计时在 Hover 中可查，不能把独立层改成共享到期。

Hover 是可复用的客户端显示模块：控件或状态提供稳定身份与只读详情值，绑定鼠标定位，统一换行、边缘避让和中英文处理，不从 Hover 中修改世界。武器详情复用已有伤害解释结果；默认显示最终数值，按住已绑定的详情键（默认 Shift）展开乘区。长武器信息可通过已有普通武器窗口阅读；Hover 不可固定或拖动，离开目标、切语言、内容失效或失焦时清理/更新显示，不保留上一物品的过期说明。设置与 Hover 均不暂停服务器。

Hover 是鼠标旁的只读信息，没有关闭键、确认/取消键，不接受拖动、固定或滚动，唯一详情交互是 Shift。普通窗口可以拖动、关闭并同时打开多个；Shift 展开 Hover 或当前普通窗口的详情，不打开全局伤害面板；具体状态左键不打开额外页面。状态 Hover 默认显示简单描述、层数和持续时间，Shift 再显示计算过程等详情。整体等级仍由正式状态数据提供，不用惩罚层数冒充等级。

## 玩家配置布局

设置提供“编辑 UI 布局”。进入后显示组件边界和拖动手柄，玩家分别移动技能栏、消耗品栏、小地图、视角按钮、队友栏、生命/资源区域、状态栏及装备入口。背包和检查窗的位置也有独立记录，显示样例便于在未打开窗口时编辑。

编辑使用草稿，提供保存、取消和恢复默认。保存完成后持久化到当前客户端 profile 的 JSON 设置；取消恢复进入编辑时的布局；恢复默认只修改草稿，保存后才生效。当前原生版用鼠标拖动，不提供草案中的方向键微调。在线打开设置/背包/地图/布局编辑不暂停服务器，也不切换普通状态的时间域；连接前可以修改设置，完整 HUD 样例依赖已连接状态。

工程数据采用版本化布局配置：稳定组件 ID、锚点与相对锚点的逻辑坐标偏移。锚点支持屏幕角、边中心及中心。不要只保存一次截图的绝对像素位置，也不要用翻译后的标题作配置键。窗口尺寸变化时重新求布局，限制组件落在可见范围；临时缩小窗口不反写原布局，以便放大后恢复。保存失败保留原配置并显示可重试反馈。

布局设置属于客户端，不写进冒险检查点、不同步给队友。现有语言、帧率、VSync 和身份配置继续保留；写入使用完整校验及文件替换，避免保存布局时丢失其他设置。缺失/旧版布局字段回退默认，非法坐标和非有限数值拒绝或回退。

模组显示组件使用命名空间 ID 和默认布局元数据。基础状态/资源展示仍复用宿主控件，不在此次引入任意 JS 绘制执行。具体组件注册契约在有实际扩展调用者时公布；移除模组后不会因为一个失效组件引用使整个 HUD 无法加载。

## 房间、连接房间与空区域

用户已选择独立房间模拟。连接区域也是完整的六边形房间，可命名为“通路”“野外”等，进入不消耗行动力。没有房间的空区域以“悬崖”“山壁”等名称和地形表达，不提供不存在的房间入口。

| 空间类别 | 权威状态与显示 | 进入规则 |
| --- | --- | --- |
| 内容房间 | 战斗、商店、事件、BOSS 等已有节点；独立空间身份和实体坐标 | 继续沿用节点费用、开门、波次加入及 BOSS 集结规则 |
| 连接房间 | 实际可行走的六边形空间，“通路”“野外”等名称 | 不消耗行动力；只能通过已连接的真实入口跨房 |
| 空区域 | 六边形棋盘中的无房间区域，“悬崖”“山壁”等地形 | 不生成房间实例，不可作为跨房目的地 |

六边形相邻不意味着自动连通，地图中只有明确连接关系才生成可通过的门/边界。连接房间不自动变成绕过战斗房间的替代路线；多数战斗不能绕过的既有规则继续成立。此阶段不为“野外”擅自加入敌人、奖励、危险或绝对安全规则。

层地图继续使用六边形拓扑，同时提供房间/地形名称、有效连接、队友位置及原有商店/BOSS 公开信息。小地图和大地图读取同一地图状态。点选地图只查看信息，不能通过点击切换玩家的节点或世界位置。

## 实际移动和行动力事务

玩家使用既有键盘/鼠标移动在房间内走动，到达实体入口后由服务端处理跨房。客户端提供移动意图和所操作的入口身份，不能提交“已抵达另一房间”、最终位置或自行扣除行动力。

服务端先检查当前空间、玩家位置、真实连接、门/节点可用性、行动力和入场时机，再预计算费用与目标入口落点，最后交接实体并提交节点访问。行动力相关操作仍是开门/入场事务；不能因玩家只是走近入口或地图选中节点就扣费。2026-10-08 已确认并接入：免费通路自动通过，个人费用门口确认，共享节点在实体装置范围内交互投票，离开范围撤票；层间出口同样使用装置而不使用投票窗口。

个人费用按进入者执行；共享开门需要原有团队决策，批准与本人是否进入分开。连接房间的费用恒为 0。已完成内容房间的可重复经过规则继续沿用，不会因每次走过连接房间而重复产生奖励。

两名玩家可在不同内容房间战斗，其他玩家可在连接房间行走。同一实体始终只有一个写入所有者：原房间停止处理它，交接完整的生命/状态/物品/输入边界数据，目标空间确认后才完成切换；失败不能留下部分费用、双重人物或没有归属的人物。交接时处理状态时间标记、输入锁存及插值历史边界。

把空间生命周期与战斗生命周期分开。没有战斗的连接房间需要移动、碰撞和入口逻辑；已清理房间仍能行走，不应因为战斗完成就销毁所有空间数据。没有玩家的空间可以按明确规则卸载，但再次载入必须保留门、完成记录和已获得收益，不重新刷新战斗奖励。

房间六边形边界、入口方向/落点、碰撞及导航数据由内容定义提供，逻辑与显示使用同一几何数据。层的轴坐标用于拓扑定位，实体使用所在房间的世界坐标；俯视/斜俯视共用这些坐标，小地图绘制坐标不能成为权威位置。房间内鼠标寻路从旧的无障碍直线升级为理解边界和阻挡的客户端导航，服务端仍验证移动。

救援继续通过实际到达可用入口并合法入场，或已有快速支援效果完成；不能用大地图点击绕过距离与费用。BOSS 和强化 BOSS 保留已确认的全队流程，不能将普通跨房入口的行为直接套给强制集结。全队集结的移动表现于对应机制接入时整理。

保持逻辑 30/60 TPS 与渲染上限独立；世界视口扩大后重新测量实际 FPS、活跃空间 TPS、导航/几何加载时间和消息大小。具体模板和资源在相应增量实施前准备，公开格式与协议版本在代码完成时更新。
