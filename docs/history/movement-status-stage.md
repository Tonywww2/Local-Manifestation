# 连续跨房、扩大场地与限时属性状态

日期：2026-10-08。当前原版包 0.4.0、网络协议 8、SDK 4、内容格式 2、检查点 4。同步更新客户端、服务端及内容目录，并开始新冒险；个人身份配置、语言、按键和 HUD 布局的文件格式不变。

## 连续移动与波次

免费非战斗房间和已清理房间的入口采用连续坐标交接。开口宽度仍为 56 世界单位，其他墙面约束完整碰撞圆。角色中心实际跨过共享边界时，服务端转换房间坐标系，保留横向位置、当刻的移动余量、位置连续序号和移动输入；不再把角色重置到固定门口落点。不同内容尺寸通过同一六边形格坐标变换拼接。

客户端允许在真实免费开口短距离延续显示预测；收到跨房快照后转换已有预测坐标、鼠标目标和瞄准坐标，不清空持续移动。显示预测不更改服务端节点、行动力或战斗身份。付费入口继续使用已确认的门口确认及服务端费用事务。

原版房间及默认非战斗房间的宽高由 800×500 调整为 2000×1250，边长为原来的 2.5 倍，面积为 6.25 倍。敌人出生半径同步扩大。角色大小、移动速度、网格单元及武器射程沿用原值。镜头使用原来的观察尺度，因此场地确实扩大，仍按玩家位置跟随；JSON 自定义房间使用自己的尺寸。

初始等待及波次间隔继续更新玩家移动、攻击、闪避、冷却、闪避回复和投射物。倒计时显示在房间中央附近，避开正中央的角色。战斗暂停仅保留全房无人存活、等待外部支援的既有规则；恢复支援时保留原来的等待/波次阶段。普通界面不提供暂停。

## 状态核心与冒险时间

本增量实现 S1/S2 中的玩家限时属性状态。`pkg/status` 是纯值核心，负责施加、满层刷新、唯一拒绝、冲突替换、独立到期、离场清除和装备绑定移除的基础函数。宿主负责内容引用、命令权限、派生属性、生命比例和一次提交；装备绑定移除的函数等待装备宿主接入。

- 来源以施加者及技能/物品实例识别。同定义的不同来源独立存在。
- 状态整体有等级，各层无等级。层和状态均有稳定 ID；最高层指最后存活的层。
- 各层保存施加时间、到期时间及当时复制的修饰值。修改定义副本或来源属性不改变既有效果。当前修饰为 JSON 固定值，动态效果计算器及特殊状态逻辑后续接入。
- 满层刷新仅改变最高层的到期时间；较低层仍按自己的时间到期。
- 唯一状态拒绝另一施加者；同施加者换来源实例时替换旧实例。声明冲突时替换冲突状态，双向声明均生效。
- 跨房默认保留到期时间；`clear_on_leave` 在实际离开节点时移除。完成战斗仍留在同一节点时保留。进入下一层和 BOSS 集结也处理实际离场生命周期。
- 属性贡献接入 `pkg/stats`，攻击及 Shift 解释使用同一份求值结果。最大生命改变保持当前生命比例，倒地和死亡身份不由属性刷新改变。

冒险时钟每秒 60000 个整数单位，30/60 TPS 分别推进 2000/1000 单位；毫秒持续时间精确换算为 60 单位。地图、层间准备及断线玩家继续计时；初始大厅和终局不推进。房间战斗暂停仍接收冒险时间、处理到期，但不更新战斗移动与战斗时钟。

协调器只修改场景外玩家，向活动 actor 传递单调冒险时间；actor 在自己的命令序列中推进状态，再处理后续战斗。快照和交接保存已处理时间，接收者处理尚未经过的部分。检查点保存完整时间及嵌套状态，恢复不扣除服务器停止期间的现实时间。

## 内容与 SDK

`definitions.json` 新增可选的 `statuses` 数组。示例用于说明格式，原版没有新增这些平衡数值：

```json
{
  "statuses": [{
    "id": "base:example-focus",
    "name": "Focus",
    "name_key": "example.focus.name",
    "description": "Increases strength.",
    "description_key": "example.focus.description",
    "level": 2,
    "max_layers": 3,
    "duration_ms": 10000,
    "unique": false,
    "conflicts": [],
    "clear_on_leave": false,
    "bound_to_source": false,
    "modifiers": [{"id":"base:example-strength","stat":"strength","operation":"add","value":5}]
  }]
}
```

Go 和 JS 节点/事件处理器返回同一种受限命令：

```javascript
return [{
    kind: "apply_status", target: ctx.player.id, status: "base:example-focus",
    source: {kind: "node", actor: ctx.player.id,
             instance: ctx.node.id, definition: ctx.node.definition}
}];
```

事件回调可从 `ctx.players` 取得上下文玩家；节点回调使用 `ctx.player`。来源定义必须引用已加载的武器、机体、敌人、节点或状态定义，实例必须非空。命令不接受客户端指定的时间或任意效果值；未知状态、非法来源或后续操作失败不会部分发放状态或扣费。

加载时校验状态 ID、冲突引用、修饰 ID、操作和有限数值。当前运行预算为每个玩家最多 16 个来源实例、总计 32 层，每层最多 8 项修饰；持续时间为 1 毫秒至一天。这些是本增量的运行预算。负百分比贡献不能依靠随后会到期的正贡献遮盖非法负乘数，施加阶段拒绝这种组合。网络帧上限提高至 4 MiB，测试覆盖八名玩家的完整预算与长 ID；后续复杂结算明细仍需摘要/详情分流。

## 状态 UI 与验证

状态栏使用真实状态实例，图标附整体等级与最早到期秒数；Hover 展示简单描述、层数及各层剩余时间，Shift 展示来源与共享属性求值的计算步骤。左键不打开页面。Hover 保持可拖动；超过可见槽位时显示更多图标，在状态栏滚动能到达每个状态。中英文词条位于 JSON 本地化文件。

验证包含：

- 六方向连续坐标变换、开口及墙体边界、预测坐标转换和持续输入。
- 30/60 TPS 等距移动、等待/波次间移动、攻击及闪避回复。
- 独立来源/层、唯一拒绝、冲突替换、满层刷新、到期及深拷贝隔离。
- JS 施加、命令批次失败回滚、生命比例、跨房保留与显式离场清除、暂停房间到期。
- 真实 TCP 免费跨房连续性、等待时移动及状态到期、分房战斗、重连、波次加入和完整三层循环。
- 八个实际连接和原生 Windows 画面：三种窗口尺寸、中英文、俯视/斜俯视、入口确认、中央字幕和状态 Hover。
- 双原生客户端：扩大房间、邻房预加载、长属性/伤害解释及开发状态；120 FPS 上限、VSync 关闭、60 TPS、输入 60 Hz。活动战斗平均 114.71 / 114.61 FPS，场景 TPS 与输入频率均为 60.00；结果为本机采样。
- 全量测试、相关竞态、vet、Windows 三个程序及 Linux 服务端构建。

后续按既有方案迁移倒地事件记录与惩罚，接入护盾、多段命中和装备/背包事务。本增量不包含完整技能库、敌人控制状态或新的正式平衡内容。
