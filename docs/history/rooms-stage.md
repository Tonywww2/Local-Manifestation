# 六边形房间与起点角色修正

日期：2026-10-08。此修正阶段网络协议升级为 6；后续已升级至协议 8，见[当前实现](movement-status-stage.md)。当时客户端和服务端一起更新；SDK 3、内容格式 2、检查点 3 保持不变。

## 问题与结果

原生 HUD 更新后，开始本层会把玩家留在起点。旧客户端仅在战斗 Scene 中绘制角色，非战斗节点只绘制节点名称，且旧服务端输入入口只转发战斗 actor，所以起点既没有可见角色，也不能进行房间内移动。

现在起点、商店及已清理节点都显示服务端裁定的角色坐标。开局分散出生，八位成员可区分；自己控制的角色有白色轮廓，队友保留蓝色表示。房间内常规移动由冒险协调器按固定 30/60 TPS 推进，不消耗行动力、不改变节点。进入战斗后由该房间 actor 接管坐标，协调器停止写入。倒地、死亡、离线、非探索阶段及输入超时不会持续走动；换层、入场及重连清理旧移动意图。

每个房间的场地改为正六边形，内部网格也是正六边形。网格是显示参考，玩家保持连续二维移动。俯视/斜俯视共用世界顶点、坐标和碰撞；相机按实际六边形轮廓适配窗口，不按旧矩形范围缩放。

## 几何与渲染

`pkg/geometry` 是纯值模块，提供正六边形顶点、带半径的占位判断和最近边界投影、线段裁剪、轴坐标网格及分散出生点。内容尺寸是包络：中心为 `(width/2, height/2)`，半径为 `min(width/2, height/√3)`。形状不会因包络比例不同而拉伸。非战斗节点暂用共享的 800×500 开发包络。

服务端对角色和敌人使用完整碰撞圆的六边形边界，弹体越界移除。出生点也遵守同一约束；鼠标点击目的地限制到可站立范围。网格线在世界坐标中裁剪，只绘制场地内部，边界外留为空区域。

房间地面、网格与轮廓按尺寸、投影和窗口变化缓存为纹理。自己角色的轮廓按像素半径缓存为小纹理，移动仅更新绘制位置；改变视角或窗口尺寸时重新构建。首次回归出现帧率下降，CPU 采样显示新增角色描边路径占据大量渲染开销，缓存后恢复基线。没有降低服务端逻辑刻或输入发送频率来改善 FPS。

## 验证

- 完整 Go 测试及 vet 通过；相关客户端、协调器、战斗场景与几何模块的竞态检查通过。
- 测试覆盖六边形顶点/边长、圆形实体在斜边和角落的约束、网格裁剪/重复边、八人出生点、弹体越界移除，以及极端房间尺寸下两种镜头的投影往返和 32 位网格索引。
- 30/60 TPS 运行相同一秒输入得到相同常规移动距离；超时、倒地、死亡、离线停止移动；不消耗行动力，不通过室内移动改变节点。
- 本机真实 TCP 测试确认开局存在合法角色坐标，并可在没有战斗 Scene 时移动。另由八个真实连接捕获起点、移动及同时在 A/B 房间战斗的快照，检查 1024×720、1280×800、1920×1080、中英文和双视角原生截图。
- 同一双客户端性能基线：120 FPS 上限、VSync 关闭、场景 60 TPS、输入 60 Hz，双方展开长伤害解释。启动两秒后的活动场景平均 FPS 为 109.56 / 104.24，场景 TPS 为 60.00 / 59.99，输入为 60.01 / 60.00 Hz。本机结果不保证其他设备达到同样帧率。
- Windows 客户端/服务端/模组工具及 Linux amd64 服务端构建通过。

此修正当时仅交付房间形状、角色显示和室内移动。后续已接入免费通路、空地形、真实入口、服务端跨房校验、周边加载与装置投票；当前范围见[跨房实现](doors-stage.md)。障碍导航等仍待后续增量。
